# A股日线自动化选股系统 · 规格（v1.0 终稿）

> 本规格由 wayfinder 地图各项决策汇总而成，决策来源以「来源：#n」标注，细节以原票为准。
> 达到可逐票实施的程度；实施拆票建议见 §13。

## 1. 目标与边界

- **目标**：A 股日线自动化选股系统，链路 = 数据获取 → 真伪过滤 → 时效判断 → 可持续性评估 → 选股筛选 → 择时入场 → 出场风控 → 回测验证。
- **AI 定位**：AI 只做分析判断（真伪/时效/可持续性），不直接决定买卖；最终决策由规则引擎完成。
- **明确不做**（out of scope）：实盘自动下单/券商 API 对接；分钟线/高频数据；新闻舆情（仅财报级公开信息）。
- **用户规模**：单用户本地系统，免费数据源起步。

## 2. 技术栈与整体架构（来源：#8）

### 2.1 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Python 3.11 + FastAPI + Pydantic v2 |
| 前端 | Vue 3 + Vite + Element Plus + ECharts |
| 数据库 | SQLite（WAL 模式），SQLAlchemy 抽象隔离方言，预留迁 PostgreSQL |
| 调度 | APScheduler + 交易日历 |
| 部署 | 开发期裸跑 uvicorn；交付单机 docker-compose（backend + frontend/nginx + SQLite 数据卷挂载） |

- OpenAPI schema 即接口契约的单一事实源；前端用 openapi-typescript 自动生成 TS 类型，不手写接口文档。
- 前端数据交互用轮询（15~60s），不引 WebSocket（留作升级项）。

### 2.2 monorepo 模块划分

```
backend/app/
  data/        # 数据层：适配器、管线、校验（#2 #3）
  analysis/    # 分析层：规则引擎 + ai/ 子模块（#4 #10）
  strategy/    # 策略层：选股、择时、出场风控（#5 #6）
  backtest/    # 回测引擎与模拟盘（#7）
  api/         # FastAPI 路由（展示层）
  scheduler/   # APScheduler 任务编排
  common/      # RiskConfig / AIConfig / 交易日历 / 工具

```

依赖单向：`data → analysis → strategy → backtest/api`；跨层只经接口调用，禁止反向 import。

## 3. 数据层规格（来源：#2 #3）

### 3.1 数据源与抽象层

- **免费起步**：akshare 为主（东财行情 + 新浪财务指标 + 乐咕估值）+ baostock 兜底（历史 K 线、isST/退市标记）。efinance 仅作临时取数工具，不作核心依赖。
- **付费档**：tushare Pro（2000~5000 积分）：财务口径最规范（update_flag 修正）、list_status 覆盖退市最可靠。
- **抽象层按数据类别划分**，可独立切换适配器：
  - `QuoteSource`：日线行情
  - `FinanceSource`：财务指标
  - `ProfileSource`：基础信息（板块/上市/退市/ST）
- 实现：`AkshareAdapter`（主力）、`BaostockAdapter`（兜底）、`TushareAdapter`（付费）。
- 统一约定：字段英文标准名；代码格式 `600519.SH`；各适配器负责转换中文列名/字符串返回。
- 必备工程件：本地落库缓存（减少重复调用规避限流）、限速重试、多源交叉校验。

### 3.2 数据库表结构（草案，实施时定列级 schema）

| 表 | 内容 |
|---|---|
| `daily_bar` | 日期、代码、开高低收（**原始不复权**）、成交量、成交额 |
| `adjust_factor` | 日期、代码、复权因子 |
| `stock_profile` | 代码、名称、上市板块、上市日、退市日、ST 状态（含历史变更留痕） |
| `finance_indicator` | 报告期、代码、ROE、增长率等指标（免费档以新浪源字段为准，付费切 tushare fina_indicator） |
| `valuation` | 日期、代码、PE、PB、股息率（乐咕源） |
| `ai_assessment` | 三判断结论、评估时点、模型版本、输入数据指纹（见 §4） |
| `ai_cost_log` | date、stock_code、model、tokens_in、tokens_out、cost_cny |
| `data_check_log` | 校验日期、类型、股票范围、结果、告警级别 |

- **复权处理**：存原始不复权价 + 复权因子表，查询时按需计算前/后复权。
- 不采用时序库：日线是低频结构化数据，SQLite + 索引可承受约 5000 股 × 8000 交易日 ≈ 4000 万行。

### 3.3 调度与更新节奏

- 按交易日历（akshare 交易日历接口）判断交易日；收盘后（约 17:00）自动跑增量；历史回补为一次性任务。
- **财务数据**：财报季（4/8/10 月披露高峰）全量重拉；按披露日历增量更新留作后续优化。

### 3.4 数据校验基线

1. **完整性**：当日应有行情股票数 vs 实际入库数，缺口留痕、次日补抓。
2. **停牌识别**：成交量=0/停牌标记区分停牌与缺失，不误报。
3. **多源对账**：抽样（随机 50 只 + 全部自选股）用 baostock 对账收盘价，超阈值告警。
4. **异常值**：涨跌幅超 ±44%（新股除外）、价格 ≤0、HLC 逻辑矛盾标记可疑。
- 财务数据校验（如 ROE 跳变检测）暂不入第一版。

## 4. AI 分析模块（来源：#4 #10）

### 4.1 角色与落库

- **真伪（authenticity）**：硬过滤器——`fail` 直接剔除候选，`suspect` 降权。
- **时效（timeliness）与可持续性（sustainability）**：加权信号——`valid_until` 过期触发重评；可持续性评分归一化后加权。
- 结论落独立表 `ai_assessment`；规则引擎把 AI 结论当**普通因子**读取。AI 挂掉/超预算时标的标「未评估」照常进池，AI 权重为 0。

### 4.2 输入（第一版仅公告/财报级信息）

- 真伪过滤：结构化财务字段 + 数据管线校验标记（多源对账/异常值）+ **原始公告全文**。
- 时效判断：公告发布日期、公告类型、当前交易日 → 输出信息有效期。
- 可持续性评估：近 N 期财报趋势序列（营收/净利润/毛利率/现金流）+ 行业对比基准（如有）。

### 4.3 输出契约（一次调用，三判断合一，Pydantic 强校验）

```json
{
  "authenticity": {"verdict": "pass|suspect|fail", "confidence": 0.0, "reasons": []},
  "timeliness":   {"valid_until": "YYYY-MM-DD", "decay_hint": "fast|medium|slow", "reasons": []},
  "sustainability": {"score": 5, "trend": "improving|stable|deteriorating", "key_risks": []},
  "evidence": [{"source": "公告/财报字段", "quote": "..."}]
}
```

不合规重试一次后降级为「未评估」。三判断共享同一次阅读理解，一次调用输出一个对象。

### 4.4 模型分层与成本控制（#10）

- **分层路由**：便宜模型（deepseek-chat / glm-4-flash 级别）批量评估全池；升级 reasoner 复核的入选标准：三判断含 `suspect`、置信度 < 0.7，或该标的当日拟买入/加仓（拟操作前强制复核）。复核结论覆盖原结论并注明复核轮次。
- **模型名仅为配置项**（配置表），不锁死厂商；API key 走环境变量。
- **成本预算**：每日费用上限（默认 ¥10/天，配置项）+ 月度预算（默认 ¥200/月）；每次调用前检查累计花费，超限当日剩余标的标「未评估」。花费记 `ai_cost_log`。
- **数据指纹与重评**：指纹 = 财务指纹（报告期 + 关键财务指标 hash，含 prompt/模型版本号）；仅财报变化触发重评，节奏对齐财报季全量重拉；日线波动不触发重评；prompt 升级或模型切换 → 全量重评一次。
- **失败与降级**：指数退避重试 3 次（5s/30s/120s）；全失败标「未评估」写入失败日志，等下个调度窗口。连续 3 个调度窗口失败 → 告警：日志 ERROR + 前台横幅「AI 评估已停 N 天」；规则引擎照常运行。
- **速率**：信号量限并发；每晚数据管线完成后触发一次全池评估；不做独立 QPS 治理。
- 配置收进统一 **AIConfig**（沿 RiskConfig 收口惯例）：费用上限、并发数、退避序列、复核阈值。

### 4.5 模块归属

全部实现在 `analysis/ai/`：LLM 客户端、模型分层路由、成本记账、指纹、退避重试、告警。

## 5. 选股规则与股票池（来源：#5）

### 5.1 初筛：硬门槛（第 0 层，触发任一即剔除，理由记录）

| # | 规则 |
|---|---|
| H1 | 非 ST、非 *ST |
| H2 | 上市满 2 年 |
| H3 | 最近一季 ROE(TTM) ≥ 8%，且最近 3 年年报 ROE 均 ≥ 5% |
| H4 | 资产负债率 < 70%（金融、地产两行业豁免，行业自适应阈值） |
| H5 | 最近一年经营现金流 > 0，且 经营现金流/净利润 > 0.5 |

### 5.2 打分排序（第 1 层）

三维度各归一化到 0~100，加权合成（质量 40% / 成长 30% / 估值 30%）：

- **质量**：ROE 水平 + ROE 3 年稳定性（标准差越小越好）+ 毛利率水平与趋势
- **成长**：营收增速（最近年报 + 最新季报）+ 净利增速，全市场标准化打分
- **估值**：PE(TTM)、PB 的「自身 5 年历史分位」与「行业内横截面分位」各占一半权重

### 5.3 股票池动态维护

- 规模 N = 80（可配置）。
- **全量重算**：财报季（4/8/10 月披露高峰后）重跑初筛、重建全池。
- **月度增量剔除**：新增 ST、退市风险警示、财报异常（衔接 AI 真伪 fail）、暴雷等触发即时移出，不重算全池。
- **跌出**：排名落入后 30% 或触发任一硬门槛 → 移出。
- **进入**：新财报后打分进入前 N → 进入；池内排序含 AI 可持续性加权信号。

## 6. 择时入场（来源：#5）

仅对股票池内个股生效：

- **核心信号（必须）**：均线趋势——收盘价上穿 MA20，或已站稳 MA20 且 MA20 上拐。
- **量价确认（必须）**：信号日成交量 ≥ 20 日均量的 1.5 倍。
- **可选激进信号（可配置开关）**：突破近 60 日高点；满足时即使量能不足也视为「中」级信号。
- **信号强度分级**：

| 级别 | 条件 | 行为 |
|---|---|---|
| 强 | 趋势 + 量价确认同时满足，且 AI 可持续性正面 | 允许入场，仓位映射见 §7 |
| 中 | 趋势满足但量能不足，或 AI 中性；或触发激进信号 | 允许入场（减仓级别） |
| 弱 | 仅单一信号 | 不入场，仅观察 |

- **AI 耦合**：加减速记分项而非一票否决——AI 正面升一级、中性不变、负面降一级；AI 不可用（未评估/挂掉）视为中性，不阻塞入场。

## 7. 出场规则与组合风控（来源：#6）

统一节奏：**每日收盘后计算、次日开盘执行**（与数据管线、AI 判断同节奏；回测与实盘口径一致）。

### 7.1 止损（取先触发者）

| 规则 | 条件 |
|---|---|
| S1 ATR 止损 | 收盘价 ≤ 入场价 − 2×ATR(14) |
| S2 逻辑止损 | 收盘价跌破 MA20 |

固定比例止损不作主机制，仅供回测调参对照。触发任一 → 次日开盘卖出。

### 7.2 止盈

移动止盈：从持有期最高收盘价回撤 **3×ATR(14) 或 8%，取较宽者** → 次日开盘全仓卖出。不分批、不设固定目标位。

### 7.3 仓位结构

- 最大同时持仓 K = 10；基准仓位 = 总资金 / K。
- 仓位映射：强信号 1.0×基准（≈10%），中信号 0.6×基准（≈6%），弱信号不入。
- 双重封顶：单票 ≤ 总资金 15%；同行业合计 ≤ 总资金 30%。
- 新信号到达但已达持仓上限：只替换最弱持仓（按打分 + AI 加权分最低者）或放弃，不超限加仓。

### 7.4 组合回撤熔断

- 净值从历史高点回撤 > 10% → 暂停一切新开仓；已有持仓按 S1/S2/止盈正常出场，不强制减仓。
- 回撤收窄至 < 5% → 恢复开仓。

### 7.5 RiskConfig（参数单一收口，YAML → Pydantic 校验）

每参数三元组「默认值 / 建议搜索区间 / 语义」，回测引擎按配置对象遍历：

| 参数 | 默认 | 区间 | 语义 |
|---|---|---|---|
| atr_multiplier | 2.0 | 1.5–3.0 | S1 止损 ATR 倍数 |
| atr_period | 14 | 10–20 | ATR 回看窗口 |
| trail_atr_mult | 3.0 | 2.0–4.0 | 移动止盈 ATR 倍数 |
| trail_pct | 8% | 5%–12% | 移动止盈回撤比例 |
| max_positions | 10 | 6–15 | 最大持仓数 |
| position_scale_strong | 1.0 | 0.8–1.2 | 强信号仓位系数 |
| position_scale_mid | 0.6 | 0.4–0.8 | 中信号仓位系数 |
| max_single_weight | 15% | 10%–20% | 单票仓位上限 |
| max_industry_weight | 30% | 20%–40% | 同行业仓位上限 |
| dd_circuit_break | 10% | 8%–15% | 熔断触发回撤 |
| dd_recover | 5% | 3%–8% | 熔断恢复线 |

回测引擎引用同一 `RiskConfig` 做参数遍历。

## 8. 回测框架与模拟盘（来源：#7）

### 8.1 引擎

**自研轻量事件驱动日线引擎**（500~1000 行量级），不采用 backtrader（停滞、需 hack）与 vectorbt（向量化难表达动态风控与 AI 信号）。与规则引擎、RiskConfig、数据表结构天然对齐。如日后需纯规则类参数批量扫荡，可另加 vectorbt 作补充，不在主引擎路径上。

### 8.2 撮合口径（参数进 RiskConfig）

- 信号日收盘决策 → 次日开盘价成交。
- 开盘价触及涨跌停视为不可成交，顺延。
- 卖出资金 T+1 可用。
- 费用：佣金 0.025%（双边，最低 5 元/笔）+ 印花税 0.05%（仅卖出）+ 固定滑点 0.1%（按开盘价）。

### 8.3 回测指标清单

总收益、年化收益、最大回撤及区间、夏普、胜率（按笔）、盈亏比、单笔最大亏损、换手率、相对沪深 300 的超额收益与相对回撤；月度收益热力表为可选展示项。

### 8.4 模拟盘

与回测共用同一套撮合逻辑与指标计算模块，喂真实每日数据：每日收盘后跑决策，次日按真实开盘价虚拟成交；成交/持仓/净值落表结构与回测一致。前台展示净值曲线、胜率、当前回撤、持仓明细。**起始资金 20 万。**

### 8.5 回测验证基线

- 区间：近 5 年日线；基准沪深 300。
- 防过拟合：2021–2023 训练调参，2024–2025 留出验证。

## 9. API 契约（FastAPI，OpenAPI 即契约）

第一版路由域（列资源与操作，字段级 schema 由实施票按 Pydantic 模型落地）：

- `GET /dashboard`：今日行动摘要、组合净值 sparkline、系统状态（数据/AI 任务健康）。
- `GET /pool`：股票池列表（打分三维分项、总分、AI 评估标签、信号强度、入池/跌出记录），支持排序筛选。
- `GET /stocks/{code}`：个股详情（K 线、估值历史分位、财务指标、AI 三判断结论、当前信号状态与理由）。
- `GET /positions`、`GET /orders`、`GET /trades`：持仓（仓位/浮盈/止损止盈线及距离）、待执行指令（收盘决策次日开盘）、历史成交。
- `GET /risk-config`：RiskConfig 只读展示。
- `POST /backtests`、`GET /backtests/{id}`：发起回测任务、取指标报告/净值 vs 沪深 300 曲线/逐笔明细。
- 前端轮询获取状态更新；所有响应模型共享 AI 三判断的 Pydantic schema。

## 10. 前台页面（来源：#9，原型变体 C「图表主导」）

第一版 5 页：

1. **仪表盘（首页）**：左侧主区为个股 K 线 + MA20 + 量能 + 信号/AI 标注（池内个股可切换）；右栏为今日行动摘要、估值分位（PE/PB 历史分位与行业分位进度条）、组合净值 sparkline；下方持仓与风控行 + 系统状态（数据任务/AI 任务健康）。
2. **股票池**：80 只列表，打分三维分项、总分、AI 评估标签、信号强度、入池/跌出记录；点击进个股详情。
3. **个股详情**：K 线 + 均线 + 量能、估值历史分位、财务指标、AI 三判断结论、当前信号状态与理由。
4. **持仓与交易**：当前持仓（仓位、浮盈、止损/止盈线及距离）、待执行指令、历史成交记录。
5. **回测**：发起回测任务、指标报表、净值 vs 沪深 300 曲线、逐笔明细。

交互约定：RiskConfig 第一版只读展示于仪表盘，编辑走配置文件，不设设置页；前端轮询 15~60s；深色主题；红涨绿跌（A 股惯例）。原型留档分支 `prototype/ui-variant-c`。

## 11. 运行时与调度（scheduler/）

- APScheduler 编排全部定时任务，集中在 `scheduler/`：
  1. 交易日历判断 → 交易日 17:00 数据管线（增量拉取 + 校验）；
  2. 数据管线完成后 → AI 全池评估（成本预算检查 → 便宜模型批量 → 复核路由）；
  3. AI 评估完成后 → 规则引擎（初筛/打分/股票池维护 + 持仓风控计算）；
  4. 次日开盘前生成待执行指令清单（模拟盘虚拟成交）；
  5. 财报季（4/8/10 月）追加财务全量重拉 + 全池重算任务。
- 告警：数据校验告警、AI 连续失败告警、成本超限告警，统一写日志 + 前台系统状态展示。

## 12. 配置收口

| 配置对象 | 收纳内容 | 位置 |
|---|---|---|
| `DataConfig` | 数据源选择（免费/付费档）、限速参数、对账抽样规则 | `common/` |
| `AIConfig` | 模型名、分层路由阈值、费用上限（日/月）、并发数、退避序列 | `common/` |
| `RiskConfig` | §7.5 全部风控/回测参数 | `common/` |

均为 YAML + Pydantic 校验；第一版前端只读展示，编辑走配置文件。
